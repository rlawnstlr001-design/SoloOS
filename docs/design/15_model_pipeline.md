# 15. 캐릭터 퀄리티 2단계 — 시범 모델 사양서와 모델 파이프라인 (2026-10-20)

14 문서 로드맵의 2단계. 영웅 1(바리공주)·보스 1(불가사리)을 외부 모델로 만들어 게임 화면에서 절차 모델과 비교한다.
이 문서는 **AI 3D 생성 도구에 넣을 때도, 외주 작가에게 맡길 때도 그대로 쓰는 사양서**다.

## 1. 공통 스타일 규칙
- **로우폴리 + 셀 셰이딩 + 외곽선.** 게임이 툰 셰이딩·외곽선을 자동으로 입히므로, 모델은 **단색 면 위주**(그라데이션·사실적 텍스처 X)가 잘 어울린다.
- **꼬마 비율 약 2.5등신**: 머리(모자·관 포함)가 키의 약 40%. 위에서 내려다보는 카메라라 **머리 위 실루엣**이 가장 중요하다.
- 색: 아군은 오방색(빨강·파랑·노랑·흰색·검정) 계열, 요괴는 탁한 색 + 발광하는 눈. 금색은 영웅·보스 장식에만.
- 금지: 일본 오니풍(뿔 + 호랑이 가죽), 실존 인물 얼굴, 지금도 모시는 신격의 희화화 (12 문서 1절).

## 2. 기술 사양
| 항목 | 일반 유닛 | 영웅 | 보스 |
|---|---|---|---|
| 형식 | `.glb` (glTF 2.0, 텍스처 포함) | 같음 | 같음 |
| 삼각형 수 | 3,000~6,000 | 5,000~10,000 | 8,000~20,000 |
| 텍스처 | 없음(정점색/단색 재질) 또는 1024² 1장 | 1024² 1장 | 2048² 1장까지 |
| 방향·원점 | Y가 위, **앞이 +Z**, 원점은 발바닥 중앙 | 같음 | 같음 |
| 크기 | 아무 크기나 가능 (게임이 키 1.45로 맞춤) | 키 1.65로 맞춤 | 키 2.2로 맞춤 |
| 자세 | 서 있는 기본 자세 (A포즈도 가능) | 같음 | 네 발 짐승은 서 있는 자세 |
| 애니메이션 (선택) | 이름에 `idle` 들어간 루프 하나면 자동 재생 | `idle` + `attack` | `idle` + `walk` |

## 3. 파일 넣는 법 (파이프라인)
- 아군: `assets/models/units/<유닛키>.glb` (예: `bari.glb`)
- 요괴: `assets/models/yokai/<외형키>.glb` (예: `bulgasari.glb`)
- 파일이 있으면 게임이 **실행 중에 직접 읽어서**(에디터 임포트 불필요) 키를 맞추고, 바닥에 세우고, 셀 셰이딩·외곽선을 입힌다.
  파일이 없으면 지금의 절차 모델을 그대로 쓴다. 발밑 원판(계열색)·등급 고리·영웅 후광은 게임이 계속 그린다.
- 유닛키·외형키 목록: `scripts/toy2_data.gd`의 `UNITS` 키, `ENEMIES`의 `look`.
- 주의: 나중에 게임을 배포 파일로 내보낼 때는 `.glb`를 함께 포함하도록 내보내기 필터에 `assets/models/*`를 추가해야 한다.

## 4. 시범 모델 브리프

### 4-1. 바리공주 (영웅, 주술 계열) — 키 `bari`
- 설화: 버려진 일곱째 공주. 저승 서천서역국에서 약수(생명수)와 꽃을 가져와 부모를 살리고 무조신(무당의 시조)이 됨. 바리공주 무가 E0020479.
- 실루엣: **족두리** + 큰 쪽머리, 넓게 퍼지는 치마, 한 손에 **버들가지(또는 생명수 병)**, 다른 손에 방울.
- 의상: 초록 원삼(혹은 녹의홍상: 초록 저고리 + 붉은 치마), 색동 소매, 금 장식 조금. 위엄 있게, 귀엽게 (희화화 X).
- 얼굴: 단정한 눈, 작은 입, 볼 연지.
- 게임 내 역할 연출: 스킬 '생명수'(모든 유닛 MP +45) → 병에서 빛이 퍼지는 동작이 있으면 좋음.

### 4-2. 불가사리 (5막 최종 보스) — 키 `bulgasari`
- 설화: 고려 말 송도. 쇠를 먹고 자라 불로만 죽일 수 있다는 괴수(불가살이, 火可殺). 불가사리 설화 E0030766, E0024904.
- 생김새 전승: 곰의 몸, 코끼리 코, 코뿔소 눈, 소 꼬리, 범의 다리 — 이 다섯 짐승 특징을 섞은 **쇠붙이 몸**.
- 실루엣: 묵직한 네 발 짐승, 등에 **쇠 가시(녹슨 못·칼날 조각)**, 앞으로 늘어진 코, 짧은 엄니, 붉게 빛나는 작은 눈.
- 재질: 어두운 쇠(회청색) + 녹(주황 갈색) 얼룩, 관절 틈에서 불빛이 살짝 새어 나옴.
- 게임 내 역할: 무인·수군(쇠붙이) 공격을 먹고, 불 속성에 약함 → "쇠를 삼키는" 입이 크게 보이면 좋음.

## 5. AI 3D 생성 경로 (권장 순서)
1. 컨셉 이미지 1장 (정면 3/4, 흰 배경, 한 캐릭터만): 이미지 생성 0.25 크레딧 안팎, 2~4장 뽑아 고르기.
   - 바리공주 프롬프트 예: `stylized low-poly chibi game character, Korean shaman princess Bari, jokduri crown, green wonsam robe with saekdong sleeves, red skirt, holding a willow branch and a brass bell, flat colors, full body, front three-quarter view, white background, toy-like, clean silhouette`
   - 불가사리 프롬프트 예: `stylized low-poly game boss monster, Korean bulgasari iron-eating beast, bear body, elephant trunk, rhino eyes, ox tail, tiger legs, dark blue-grey iron skin with rust patches, rusty spikes on its back, glowing red eyes, flat colors, full body, three-quarter view, white background`
2. 이미지 → 3D: `meshy_v7_image_to_3d` (model_type `lowpoly`, 텍스처 켬) 또는 `tripo_h3_1_image_to_3d`. 1회 약 25 크레딧, 재시도 포함 모델당 50 크레딧 안팎.
3. 받은 `.glb`를 3절 경로에 넣고 게임에서 확인 → 6절 기준으로 평가.
- 예상 비용: 시범 2종 **약 50~100 크레딧** (Higgsfield 기준). 현재 잔액 0.52 → 충전이 필요.
- 대안: 개발자가 Meshy·Tripo 웹사이트 무료 체험으로 직접 만들어 `.glb`만 넘겨줘도 된다.

## 6. 외주 경로 (크몽·아트스테이션 등)
- 위 2·4절을 그대로 전달. 납품물: `.glb` 1개 + 컨셉 시트(정면/측면/후면) + 원본 파일, 상업적 이용 가능 라이선스 명시.
- 시안 1회 → 수정 2회. 단가는 작가·난이도에 따라 크게 다르므로 2~3명에게 견적을 받아 비교한다 (영웅 1·보스 1부터).

## 7. 평가 기준 (시범 모델이 들어오면)
1. **게임 줌에서 누군지 바로 보이는가** (절차 모델보다 나은가)
2. 셀 셰이딩·외곽선을 입혔을 때 다른 모델들과 **스타일이 섞이는가**
3. 성능: 화면에 영웅 4~6명 + 보스가 동시에 있어도 프레임 유지
4. 비용·시간: 모델당 크레딧/금액, 정리에 든 시간 → 60종 전체로 환산
→ 결과에 따라 3단계(영웅 13 → 보스 7 → 유닛 → 요괴) 제작 방식을 정한다.

## 8. 파이프라인 검증 (2026-10-20)
- 절차 모델(바리공주·불가사리)을 일부러 **3배 크기**로 `.glb`로 내보낸 뒤, 테스트 폴더에서 다시 읽어 들여 게임에 배치.
  - 결과: 둘 다 정상 로드. 키가 자동으로 맞춰지고(영웅 1.65·보스 2.2) 발이 바닥에 붙음. 셀 셰이딩·외곽선·계열 원판·영웅 후광 정상.
  - `.glb`가 없을 때는 절차 모델로 돌아감 (봇 테스트 결과 변화 없음). 테스트 파일은 지웠다.
- 아직 확인 못 한 것: 실제 AI 생성/외주 모델 (뼈대·애니메이션 포함 파일 포함). 크레딧 또는 외주 결정 후 진행.

## 9. 현재 상태와 결정할 것
- Higgsfield 잔액 0.52 크레딧 (무료 플랜) → 시범 2종(약 50~100 크레딧)을 만들려면 충전이 필요하다.
- 선택지: (a) 크레딧 충전 후 여기서 바로 생성, (b) 개발자가 Meshy·Tripo 웹 무료 체험으로 만들어 `.glb`를 `assets/models/`에 넣기,
  (c) 6절 브리프로 외주 견적 받기. 어느 쪽이든 파일만 넣으면 게임에 바로 반영된다.

## 10. 컨셉 시트 (2026-10-20, Gemini 나노바나나)
크롬의 Gemini 앱에서 이미지 생성(나노바나나)으로 만든 4면 컨셉 시트. 원본 2752×1536 PNG.
- `concepts/bari_turnaround.png` — 바리공주: 정면 · 3/4 · 옆 · 뒤. 족두리, 쪽머리, 초록 원삼 + 색동 소매, 붉은 치마, 버들가지와 방울. 사양서(4-1절)와 잘 맞는다.
- `concepts/bulgasari_quadruped_turnaround.png` — 불가사리 네 발 버전: 옆 2 · 3/4 · 정면 · 뒤. 쇠 판갑과 녹, 등줄기 못·칼날 가시, 코끼리 코, 엄니, 붉은 눈, 범 무늬 다리, 소 꼬리.
  바리공주보다 덜 꼬마 비율(코끼리·멧돼지에 가까운 체형). 같은 채팅에서는 두 발 버전만 반복돼서, 새 채팅에서 네 발을 처음부터 묘사해 얻었다.
- 쓰는 법: 이 시트를 Meshy·Tripo의 **멀티뷰 → 3D**(뷰를 잘라 2~4장으로)에 넣거나, 외주 작가에게 컨셉 시트로 전달한다.
- 주의: Gemini 생성 이미지는 오른쪽 아래에 작은 별 표시와 SynthID 워터마크가 있다. 컨셉·참고용으로 쓰고, 최종 게임 에셋은 이를 바탕으로 새로 만든 3D 모델로 한다.
